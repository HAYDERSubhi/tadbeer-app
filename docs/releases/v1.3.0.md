## ما أُضيف

**أداة «سفراتي» — الأداة الثامنة.** تحديد ميزانية لسفرة، وتسجيل مصاريفها، ومراقبة السقف، دون إغراق ميزانية الشهر إلا باختيار صريح.

| الشاشة | الوظيفة |
|---|---|
| قائمة السفرات | نشطة أعلى، وأرشيف المنتهية أسفل (قابل للطي) |
| إنشاء سفرة | ستة حقول + خيار الاحتساب بميزانية تدبير |
| لوحة السفرة | «المتبقي» هو الرقم البطل · توزيع التصنيفات · قائمة تتبع طور السفرة |
| تعديل السفرة | كل الحقول، وتغيير خيار الاحتساب يُعيد وسم كل المصاريف دفعةً واحدة |
| تعديل/حذف مصروف | تعديل وحذف فقط — الإضافة من شاشات تدبير حصراً |
| الملخص والإغلاق | ملخص مالي · تقسيم «قبل السفر/أثناء السفر» · تحليلات · زر الاحتساب |

**المعمارية:** لا كيان منفصل لمصروف السفرة — هو نفس سجل `Expense` بحقلين اختياريين (`tripId`, `tripCategory`)، فلا منطق مزامنة ولا ازدواج ممكن بحكم البنية.

## ما تغيّر بالشاشات المشتركة

كلها **إضافات أو عناصر مشروطة**. لا حذف لسلوك قائم، ولا تغيير لتوقيع دالة، ولا تعديل لشكل استعلام حالي.

| الشاشة | ما ظهر فيها | متى يظهر |
|---|---|---|
| الشاشة الرئيسية | أيقونة «سفراتي» بشريط الأدوات (صارت ثماني أدوات) | **دائماً** |
| صفحة الأدوات | بطاقة «سفراتي» (صارت ثماني بطاقات) | **دائماً** |
| إضافة مصروف · نموذج الصوت · مسح الفاتورة | مربع «ضمن سفرة» + التصنيف الثماني بدل الاثني عشر | **فقط بوجود سفرة غير مُغلقة** |
| تعديل مصروف | نفس المربع لتصحيح وسم منسي أو خاطئ | **فقط بوجود سفرة غير مُغلقة** |
| شاشة المصاريف · الإحصائيات · التقرير | فئة «سفر» باسمها وأيقونتها ولونها | **فقط عند وجود مصروف سفرة** |

**نقطتان مُنعتا عمداً:** زر «تم الدفع» بالفواتير القادمة، والاستيراد من ملف. كلتاهما تنشئ مصاريف مشتقّة لا يكتبها المستخدم لحظياً — ووسمها تلقائياً يخرّب رقم السفرة بصمت.

## ماذا يرى المستخدم الحالي

**المستخدم الذي لا ينشئ أي سفرة:** يرى **أيقونة جديدة واحدة** بشريط أدوات الشاشة الرئيسية وبطاقة بصفحة الأدوات. **ولا شيء غير ذلك إطلاقاً** — لا عنصر جديد بشاشات الإدخال، ولا خطوة إضافية، ولا اختلاف برقم واحد بميزانيته أو إحصائياته أو سلاسله أو أوسمته.

**المستخدم الذي ينشئ سفرة:** يظهر مربع «ضمن سفرة» بشاشات الإدخال الثلاث — مؤشَّراً افتراضياً **فقط ضمن أيام السفرة الفعلية**، وغير مؤشَّر قبلها (الحجوزات) وبعد عودته.

---

## ⛔ لا هجرة بيانات ولا كتابة على مستندات قائمة

- **لا سكربت هجرة، ولا كتابة دفعية، ولا تعديل تلقائي على أي مستند قائم.** لا شيء يعمل عند النشر.
- الحقلان `tripId` و`tripCategory` **اختياريان**، ولا يُكتبان إلا على مصروف يوسمه المستخدم بنفسه.
- المصاريف القديمة تبقى كما هي **حرفياً** — بايت ببايت.
- **لا تعديل على `firestore.rules`** — قاعدة `users/{uid}/{document=**}` تغطّي مسار `trips` أصلاً.
- **لا فهرس Firestore جديد** — استعلام السفرة بحقل واحد، والترتيب بالجافاسكربت عمداً.
- فئة «سفر» **لا تُحفَظ ضمن فئات المستخدم**؛ حارس بـ`updateUserSettings` يمنع ذلك حتى لو مرّت قائمة شاملة من أي شاشة حفظ.

## التحقق المُنجَز فعلياً (لا نظري)

- **حساب اختباري (ضيف)** لا حساب شخصي — قاعدة `12.5-أ`.
- الشاشات الست مُجرَّبة بمعاينة جوال 375px، بالوضعين الفاتح والداكن.
- **ثغرة العائلة (الحالة ١١):** سفرة بـ24,500 د.ع — أُنشئت عائلة (انتقلت المصاريف لمسارها) ثم حُذفت (رجعت للمسار الشخصي). **الرقم بقي 24,500 في الحالات الثلاث.**
- **الاستيراد من ملف:** صف فئته «سفر» حرفياً نزل «متفرقة» بلا أي وسم رغم وجود سفرة نشطة.
- **مسح فاتورة:** ثلاثة عناصر استُخرجت وحُفظت باختيار سفرة واحد.
- **اتجاه أشرطة التقدّم:** قيس هندسياً — حافة التعبئة اليمنى تطابق حافة الحاوية بثلاثة أشرطة.
- `npm run typecheck`: **٨ أخطاء داخل `src/` = خط الأساس المسجَّل قبل بدء العمل**، بلا زيادة.
- **بيانات الاختبار حُذفت بالكامل** بعد كل جولة (صفر مصاريف وصفر سفرات).
